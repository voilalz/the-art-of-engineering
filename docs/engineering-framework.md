# 工程共性能力框架

工程系统的结果取决于专业设计，也取决于各项设计之间的关系：指标怎样传递，基准是否统一，误差是否相关，接口和时序是否匹配，测量能否支撑结论，变更之后证据是否仍然成立。

这份框架用于处理这些关系。使用时，选择一个具体任务，从它的需求、模型、预算、接口和验证记录开始，逐步补齐关键缺项。可以配合[任务记录模板](../templates/engineering-task.md)使用。

## 怎样找到当前最需要的方法

| 任务中的信号 | 先检查什么 | 需要补齐的工作产物 |
| --- | --- | --- |
| 指标含糊，团队理解不一致 | 对象、工况、单位、基准与统计含义 | 可判定的需求、物理量字典 |
| 参数很多，不知道结果是否可能 | 数量级、守恒、上下界、模型假设 | 最小模型与独立校核 |
| 部件都达标，整机不达标 | 指标组合、耦合、共享误差与接口损失 | 可回算的指标与误差预算 |
| 一运动、一升温或一切换就异常 | 时间、热、载荷、饱和、状态前提 | 时序预算、运行包络、状态转换表 |
| 仿真和试验对不上 | 测量链、参数来源、数值误差和模型边界 | 标定、收敛与独立验证记录 |
| 故障偶发，反复修改仍无解释 | 配置、复现条件、测点和可证伪假设 | 问题证据链与分段定位记录 |
| 换件、换批次或运行一段时间后退化 | 制造差异、环境、老化与变更影响 | 关键特性清单和复验依据 |
| 报告通过，交付结果不能复现 | 统计判据、配置组合、原始数据和处理版本 | 验证矩阵、配置与证据索引 |

以下方法可以在任务中交替使用。实测结果更新模型，模型改变预算，预算变化影响接口与验证；一次通过不意味着后续变更无需重新检查。

## 定义对象，统一工程语言

首先写清要改变或保证的结果。一个可使用的要求至少包含对象、条件、被测量或功能、阈值及判定方式。例如，“定位精度高”需要进一步说明测量哪个点、哪个方向、相对哪个基准、在何种速度和温度下、要求最大误差还是某个分位值。

同时确定系统边界。外部供电、参考时钟、安装基础、操作步骤、通信服务与测量设备都可能成为设计成立的前提。它们不在产品内部，也需要作为明确依赖记录。

| 要统一的内容 | 实际容易出现的差异 | 建议的检查动作 |
| --- | --- | --- |
| 单位与量纲 | mm 与 m，角度与弧度，功率与能源 | 关键关系逐项量纲校核，保留换算样例 |
| 参考点与基准 | 传感器位置与功能作用点不同 | 在图纸和模型中指明测量点、安装点与作用点 |
| 坐标与符号 | 轴方向、旋转顺序、正负号不同 | 用一个已知方向或位姿检查双方解释 |
| 时间含义 | 采样时刻、发送时刻与到达时刻混用 | 追踪一次数据从发生到执行的全链路 |
| 信号口径 | 峰值、有效值、平均值互换 | 在接口与报告中保留定义和处理方式 |
| 统计含义 | 标准差、最大允许误差、覆盖区间混用 | 数字旁注明分布/边界、工况与证据 |

**工作产物：** 问题定义、带条件的需求、物理量与基准字典。检查标准是另一位工程师可以依据这些材料建立同一个问题，而不必猜测关键定义。

对“精度、误差、分辨率、精密度和不确定度”的具体区别，参见[测量性能概念辨析](concepts/measurement-performance.md)。

## 用最小模型建立可检查的关系

详细设计之前，先用少量参数估计结果的区间。量纲、数量级、能量与质量守恒、上下界和极限工况，可以较早发现不可能的指标和输入错误。

模型复杂度随决策需要增加。静态选型可能只需要代数关系；研究瞬态需要动态模型；热梯度、柔性或空间分布决定结果时，再引入相应分布模型。每增加一个参数，都应考虑它的来源、可辨识程度和对结论的影响。

一份可用的模型说明至少记录：

- 输入、输出、单位、基准和方程。
- 边界条件、初始条件、负载与环境范围。
- 参数来自实测、资料、拟合还是暂定假设。
- 线性、稳态、独立性等近似成立的条件。
- 模型能支持什么决策，什么变化会使其失效。
- 一个解析特例、独立计算、守恒关系或试验对照。

数值计算还需要检查尺度、浮点精度、积分步长、离散化、求解器容差和收敛。软件报告“求解成功”只能说明求解过程满足相应条件，工程结论仍需对照物理模型和数据。

**工作产物：** 模型卡片、可行性估算、数值与独立校核记录。检查时应能分开解释数值误差、参数不确定性和模型误差。

## 让指标、误差和资源预算能够回算

总体要求应通过物理关系传到子系统，再用子系统能力综合回总体。功能分配回答由谁完成某个动作；性能分配回答每个环节允许多大的损失、误差、延迟或资源消耗。

组合规则随指标改变。质量通常按配置求和；能源需要结合功率和运行时间；吞吐量可能受瓶颈约束；精度需要灵敏度和相关性；响应性能可能依赖整个动态系统。分解表必须和综合模型一起维护。

### 误差分配需要先回答的问题

1. 总体指标约束的是哪个输出，属于最大边界、标准差、RMSE 还是分位值？
2. 各项误差通过什么关系作用到输出，哪些只是同一来源的不同表现？
3. 哪些可以修正，哪些是残余偏差、随机分量或尚不清楚的模型误差？
4. 各项是否共享基准、温度、时间源、设备或原始数据？
5. 给部件提出更严格要求后，成本、资源、标定和验证能力怎样变化？

误差的正向综合、指标的反向分配、样机的实测确认是三个动作。等分可以生成初始方案，最终应由灵敏度、相关性、部件能力、成本和可验证性决定。

测量误差是相对参考值的差异，测量不确定度用于表征结果所附带的分散性。A 类、B 类是评定途径，不能简单对应为随机误差和系统误差。标准差也不能直接作为确定性最坏边界。[S3][S4]

参见[误差预算案例](../examples/error-budget.md)，其中给出了一阶传播、独立和相关两种假设下的计算，以及残余偏差的处理。

灵敏度系数需要同时说明输入、输出、单位和工作点，不能只按偏导数数值大小判断贡献。测量斜率、参数相对灵敏度与反馈灵敏度函数的关系，参见[系统灵敏度辨析](concepts/sensitivity.md)。

### 资源预算需要保留工况

| 资源 | 需要单独说明的口径 | 容易遗漏的条件 |
| --- | --- | --- |
| 质量、空间与载荷 | 配置、安装方式、重心或作用点 | 连接件、线缆、支架和装配余量 |
| 功率与能源 | 峰值、平均值、占空比、持续时间 | 启动、加速、并发负载和转换损耗 |
| 热 | 产生、传递、散出和温度限制 | 环境温度、热惯性、接触与降额 |
| 带宽与计算 | 峰值流量、处理开销和共享竞争 | 协议开销、突发数据、异常重试 |
| 时间 | 各段延迟、抖动和截止期 | 最坏执行、排队、同步与模式切换 |

**工作产物：** 指标分解与回算表、误差预算、按工况分列的资源账本和取舍依据。检查时应能指出最紧约束、主要贡献项和预留量的定义；预留量不能被多个团队重复使用。

## 把接口、时序与运行前提一起设计

接口需要说明双方如何相互作用。机械连接之外，还有载荷、热、电气参考、阻抗、数据语义和操作者动作。接口定义应覆盖正常工作，也应覆盖无效输入、超时、断连、恢复和版本不匹配。[S2]

对于一项传感器数据，至少可以沿着“物理事件—采样—处理—传输—使用—执行”追踪时间。同步、固定延迟、随机抖动和时钟漂移对系统的影响不同。移动对象的位置误差可在适当近似下用速度乘以时间误差估计；反馈系统还需要检查延迟对稳定性的影响。

物理耦合同样需要分析。负载改变可能引起压降、温升、变形和振动，继而改变传感器或执行器的表现。对执行器，幅值限制、速率限制和持续工作能力应进入模型；对电源和热设计，峰值和累积效应分别校核。

运行状态决定哪些设计条件已经成立。启动、预热、自检、标定、就绪、工作、降级和停机之间，需要明确进入条件、退出条件、超时和恢复路径。稳态试验无法替代这些转换过程的验证。

**工作产物：** 接口控制文件、端到端时序预算、状态转换表和运行包络。检查标准是接口双方能分别实现并正确处理异常，系统不会在前提缺失时进入不允许的工作状态。

## 让测量、数据与参数支撑结论

先定义被测量，再选择测量链。分辨率、重复性、准确度和量程分别描述不同能力；设备标称参数也不能代替当前安装、环境和校准状态下的测量能力。

标定提供输入与输出之间的关系，调整改变设备或模型；标定后仍需记录残余不确定度、适用范围和重新标定的依据。参考设备和产品共享同一基准时，验证可能无法暴露部分共同误差，应在测量方案中分析。

原始数据、处理数据和展示数据应可区分。保留时间戳、单位、有效性、配置与处理参数。滤波可能改善噪声，也会改变幅值、相位、峰值和延迟；异常值处理应保留规则和被排除的数据，避免结果无法复现。

辨识参数时，需要保证试验对相关参数具有足够信息。拟合与验证使用适当独立的数据或工况，检查残差和参数区间。对经验模型与 AI 模型，还要说明训练、标定、验证与使用范围的关系，评估外推风险。

**工作产物：** 测量链、标定记录、数据处理说明、参数来源和独立验证结果。检查时，另一位工程师应能从原始数据复现关键图表，并解释测量能力对结论的限制。

## 用逐级集成和可证伪假设定位问题

集成顺序按依赖关系设计。先确认接口和已知输入下的行为，再逐步引入真实负载、共享资源、动态工况和异常。每一步保留可恢复的配置及通过条件，使新问题的范围可以限制在较少的变化中。

故障记录先写事实：什么设备和版本，在什么条件下，出现了什么现象，发生顺序和数据是什么。随后提出能够被实验推翻的假设，设计分段测量、替代、对照或条件控制来区分原因。

| 容易无效的做法 | 更有信息量的动作 |
| --- | --- |
| 同时换件、改参数、改程序后宣布修复 | 记录每次变化，隔离关键因素，再检查交互作用 |
| 只有最终输出，没有中间测点 | 在关键关系两端建立观测，比较输入、预测和输出 |
| 把时间先后直接视为因果 | 通过对照、替代或受控干预检查解释 |
| 只验证正常运行 | 在原复现条件、边界和相关场景中回归 |

软件、处理器和硬件在环可按任务需要使用，选择依据是需要隔离哪类误差与风险。工具名称本身不决定证据强度。

**工作产物：** 集成阶梯、问题记录、假设与证据、修复和回归结果。检查时，根因解释应能覆盖原始现象，修复应能在同样条件下复测。

## 为制造差异、失效和长期使用保留空间

单台样机证明一次实现可行；制造与长期运行还会引入尺寸差异、装配、批次、环境、磨损和老化。关键特性应从系统功能传到制造与检验，再由实际数据确认一致性。

可靠性、可用性、安全性与性能是不同的判断维度。可以使用 FMEA 梳理失效原因与影响，用故障树检查多个事件如何组合。冗余需要同时考虑故障检测、切换覆盖和共同原因；两个部件共享供电、环境或软件时，不能直接假定独立。

规定故障后的可接受行为：停机、保留某种有限能力、告警、等待人工处理或按条件恢复。维护、重标定、更换与现场反馈应连接到模型、预算和验证，而不仅是独立的售后记录。

**工作产物：** 关键失效与制造特性清单、环境验证项、降级与恢复逻辑、维护和复验依据。检查时应能回答“哪项变化会先影响什么结果，如何发现，如何处置”。

## 将验证、配置和方法资产连接起来

验证检查设计输出是否满足规定要求，确认检查系统是否适合预期用途。两者都需要在需求形成时考虑。[S1] 一个不可测或口径不清的指标，会在交付阶段转化为无法收敛的争论。

为每项关键要求指定分析、检查、演示或试验方法，说明工况、设备、样本和判据。均值、分位数、最大值、置信度和覆盖概率支持不同结论；重复测量还需要考虑样本独立性、相关性和工况覆盖。

例如，在独立同分布的伯努利模型下，3000 次零失败，对失败概率的单侧 95% 置信上限约为 0.10%。报告“零失败”应连同样本数、模型假设和覆盖范围，不能直接推导失败概率为零。

配置基线同时包含实物、装配、固件/软件、参数、标定、模型、数据处理和工具版本。交付证据应指向这一组合。设计或环境改变后，需要重新评估哪些旧分析和试验仍然有效。[S5]

工程基础库可以由脚本、计算表、模板、测量流程和参考样例共同组成。复用前检查输入、单位、条件和版本；每项资产保留正常例、边界例、验证依据与适用范围。反复复制本身不能证明其可靠。

**工作产物：** 需求验证矩阵、统计试验记录、配置与证据索引、可复用方法包。最终应能说清哪一套配置、在什么条件下、依据什么证据、支持什么结论。

## 变更时怎样重新检查

| 变化 | 优先重新检查 |
| --- | --- |
| 改变总体指标或使用工况 | 模型适用范围、误差/资源预算、边界和验收判据 |
| 更换传感器或安装位置 | 基准、标定、时间语义、误差、供电和接口 |
| 改滤波、软件或处理频率 | 幅相与延迟、负载、数据处理、版本和回归 |
| 更换电源、驱动或机械结构 | 峰值、热、载荷、耦合、饱和和异常行为 |
| 更换供应商、工艺或批次 | 关键特性、一致性、资料口径和抽样验证 |
| 扩大环境或运行时间范围 | 漂移、老化、可靠性、维护与重新标定 |

## 如何判断能力已经形成

共性能力首先表现为能够解释、能够检查，并能独立完成一个小任务。跨专业骨干还需要把多个专业的模型、预算、接口与验证组织在一起。复杂热、结构、电磁、控制等问题，再按岗位与项目要求深化。

可以用六个问题自查：

- 能否把模糊需求改写为双方理解一致的通过条件？
- 能否对关键结论做数量级或独立方法校核？
- 能否将部件能力综合回总体要求，并解释相关性和余量？
- 能否规定正常与异常接口行为，并追踪关键时间链？
- 能否设计测量和对照试验，逐步缩小故障原因？
- 能否把结果连同配置、原始数据、模型和限制交给另一位工程师复现？

这些能力通过反复完成任务及复盘积累。建议优先选择指标分解、误差分配、接口联调或一次故障定位，形成一份完整记录，再逐步增加复杂度。

- **[S1]** [NASA：Fundamentals of Systems Engineering](https://www.nasa.gov/reference/2-0-fundamentals-of-systems-engineering/)，用于对照需求、架构、取舍与验证/确认。
- **[S2]** [NASA：Interface Management](https://www.nasa.gov/reference/6-3-interface-management/)，用于对照接口定义、兼容性、变更和集成。
- **[S3]** [JCGM 100:2008 第 5 节，ISO 官方在线正文](https://www.iso.org/sites/JCGM/GUM/JCGM100/C045315e-html/C045315e_FILES/MAIN_C045315e/05_e.html)，用于对照灵敏度、标准不确定度传播与相关性。
- **[S4]** [BIPM：Guides in Metrology](https://www.bipm.org/en/web/guest/publications/guides)，用于选择测量模型、不确定度、蒙特卡洛传播和符合性评定资料，版本以官方目录为准。
- **[S5]** [NASA：Crosscutting Technical Management](https://www.nasa.gov/reference/6-0-crosscutting-technical-management/)，用于对照需求、接口、风险、配置、数据与决策的联系。
