# 工程共性能力框架

工程系统的结果取决于专业设计，也取决于各项设计之间的关系：指标怎样传递，基准是否统一，误差是否相关，接口和时序是否匹配，闭环是否有足够裕度，危险是否被识别和控制，测量能否支撑结论，变更之后证据是否仍然成立。

这份框架用于处理这些关系。使用时，选择一个具体任务，从它的要求、模型、预算、接口和验证记录开始，逐步补齐关键缺项。可以配合[任务记录模板](../templates/engineering-task.md)使用。全库用词以[术语约定](terminology.md)为准，例如“要求”与“需要”、“余量”与“裕度”、“故障”与“失效”的区分。

“问题与模型”的首篇完整正文为[第1章：从一句要求，到一个工程问题](problem-and-model/ch01-from-request-to-engineering-problem.md)，对任务、场景、边界和模型作出定义，并通过公式与算例讨论数值要求的形成和证据。

[第2章：单位、基准与坐标](problem-and-model/ch02-units-datums-and-coordinates.md)继续统一数据语义，重点区分运动参考、求导参考与分量表达基，并提供[物理量与基准字典模板](../templates/physical-quantity-reference-dictionary.md)。

[第3章：数量级、量纲与极限](problem-and-model/ch03-orders-dimensions-and-limits.md)讨论早期可行性判断，推导方向可靠的上下界，并用时间、力、能量和功率互相校核。配套提供[一页可行性估算模板](../templates/feasibility-estimate-and-cross-check.md)。

## 怎样找到当前最需要的方法

| 任务中的信号 | 先检查什么 | 需要补齐的工作产物 |
| --- | --- | --- |
| 指标含糊，团队理解不一致 | 对象、工况、单位、基准与统计含义 | 可判定的要求、物理量字典 |
| 参数很多，不知道结果是否可能 | 数量级、守恒、上下界、模型假设 | 最小模型与独立校核 |
| 部件都达标，整机不达标 | 指标组合、耦合、共享误差与接口损失 | 可回算的指标与误差预算 |
| 方案争论不休，或同类技术问题反复出现 | 判据与权重、关键不确定性、技术成熟度 | 权衡记录、风险登记 |
| 一运动、一升温或一切换就异常 | 时间、热、载荷、饱和、状态前提 | 时序预算、运行包络、状态转换表 |
| 闭环振荡、超调或参数反复调不好 | 带宽、稳定裕度、延迟、饱和与结构模态 | 控制性能规格与回路模型 |
| 仿真和试验对不上 | 测量链、参数来源、数值误差和模型边界 | 标定、收敛与独立验证记录 |
| 同一零件换人或换量具测，结果不一致 | 重复性、再现性、测量能力与判定规则 | 测量系统分析记录 |
| 故障偶发，反复修改仍无解释 | 配置、复现条件、测点和可证伪假设 | 问题证据链与分段定位记录 |
| 换件、换批次或运行一段时间后退化 | 公差堆叠、过程能力、环境、老化与变更影响 | 关键特性清单和复验依据 |
| 人员、设备或环境可能受到伤害 | 危险源、可预见误用、安全状态与反应时间 | 危险日志、安全要求及完整性等级 |
| 报告通过，交付结果不能复现 | 统计判据、配置组合、原始数据和处理版本 | 验证矩阵、配置与证据索引 |

以下方法可以在任务中交替使用。实测结果更新模型，模型改变预算，预算变化影响接口与验证；一次通过不意味着后续变更无需重新检查。危险识别和“怎样证明满足要求”应在形成要求时就开始考虑，等到样机阶段再补，通常只能靠增加防护或缩小适用范围来弥补。

## 定义对象，统一工程语言

首先写清要改变或保证的结果。一个可使用的要求至少包含对象、条件、被测量或功能、阈值及判定方式。例如，“定位精度高”需要进一步说明测量哪个点、哪个方向、相对哪个基准、在何种速度和温度下、要求最大误差还是某个分位值。单条要求的质量特征（必要、无歧义、可验证、可实现等）可对照 ISO/IEC/IEEE 29148。[R7]

同时确定系统边界。外部供电、参考时钟、安装基础、操作步骤、通信服务与测量设备都可能成为设计成立的前提。它们不在产品内部，也需要作为明确依赖记录。

| 要统一的内容 | 实际容易出现的差异 | 建议的检查动作 |
| --- | --- | --- |
| 单位与量纲 | mm 与 m，角度与弧度，功率与能量 | 关键关系逐项量纲校核，保留换算样例 |
| 参考点与基准 | 传感器位置与功能作用点不同 | 在图纸和模型中指明测量点、安装点与作用点 |
| 坐标与符号 | 轴方向、旋转顺序、正负号不同 | 用一个已知方向或位姿检查双方解释 |
| 时间含义 | 采样时刻、发送时刻与到达时刻混用 | 追踪一次数据从发生到执行的全链路 |
| 信号口径 | 峰值、有效值、平均值互换 | 在接口与报告中保留定义和处理方式 |
| 统计含义 | 标准差、最大允许误差、覆盖区间混用 | 数字旁注明分布/边界、工况与证据 |
| 用词 | 需求/要求、偏差/误差、余量/裕度混用 | 按[术语约定](terminology.md)书写，首次出现附英文 |

**工作产物：** 问题定义、带条件的要求、物理量与基准字典。检查标准是另一位工程师可以依据这些材料建立同一个问题，而不必猜测关键定义。

对“精度、误差、分辨率、精密度和不确定度”的具体区别，参见[测量性能概念辨析](concepts/measurement-performance.md)；标准差、RMS、RMSE、最大误差与分位值的关系，参见[误差统计口径辨析](concepts/error-statistics.md)。

## 用最小模型建立可检查的关系

详细设计之前，先用少量参数估计结果的区间。量纲、数量级、能量与质量守恒、上下界和极限工况，可以较早发现不可能的指标和输入错误。

模型复杂度随决策需要增加。静态选型可能只需要代数关系；研究瞬态需要动态模型；热梯度、柔性或空间分布决定结果时，再引入相应分布模型。每增加一个参数，都应考虑它的来源、可辨识程度和对结论的影响。

一份可用的模型说明至少记录：

- 输入、输出、单位、基准和方程。
- 边界条件、初始条件、负载与环境范围。
- 参数来自实测、资料、拟合还是暂定假设。
- 线性、稳态、独立性等近似成立的条件。
- 模型能支持什么决策，什么变化会使其不再适用。
- 一个解析特例、独立计算、守恒关系或试验对照。

数值计算还需要检查尺度、浮点精度、积分步长、离散化、求解器容差和收敛。软件报告“求解成功”只能说明求解过程满足相应条件，工程结论仍需对照物理模型和数据。

**工作产物：** 模型卡片、可行性估算、数值与独立校核记录。检查时应能分开解释数值误差、参数不确定性和模型误差。

## 让指标、误差和资源预算能够回算

总体要求应通过物理关系传到子系统，再用子系统能力综合回总体。功能分配回答由谁完成某个动作；性能分配回答每个环节允许多大的损失、误差、延迟或资源消耗。

组合规则随指标改变。质量通常按配置求和；能量需要结合功率和运行时间；吞吐量可能受瓶颈约束；误差需要灵敏度和相关性；响应性能可能依赖整个动态系统。分解表必须和综合模型一起维护。

### 误差分配需要先回答的问题

1. 总体指标约束的是哪个输出，属于最大边界、标准差、RMSE 还是分位值？
2. 各项误差通过什么关系作用到输出，哪些只是同一来源的不同表现？
3. 哪些可以修正，哪些是残余偏差、随机分量或尚不清楚的模型误差？
4. 各项是否共享基准、温度、时间源、设备或原始数据？
5. 给部件提出更严格要求后，成本、资源、标定和验证能力怎样变化？

误差的正向综合、指标的反向分配、样机的实测确认是三个动作。等分可以生成初始方案，最终应由灵敏度、相关性、部件能力、成本和可验证性决定。

测量误差是测得值与参考值之差；测量不确定度是依据所用信息、表征赋予被测量的量值分散性的非负参数。A 类、B 类是评定途径，不能简单对应为随机误差和系统误差。标准差也不能直接作为确定性最坏边界。[R3][R4]

参见[误差预算案例](../examples/error-budget.md)，其中给出了一阶传播、独立和相关两种假设下的计算，以及残余偏差的处理。

灵敏度系数需要同时说明输入、输出、单位和工作点，不能只按偏导数数值大小判断贡献。测量斜率、参数相对灵敏度与反馈灵敏度函数的关系，参见[系统灵敏度辨析](concepts/sensitivity.md)。

### 资源预算需要保留工况

| 资源 | 需要单独说明的口径 | 容易遗漏的条件 |
| --- | --- | --- |
| 质量、空间与载荷 | 配置、安装方式、重心或作用点 | 连接件、线缆、支架和装配余量 |
| 功率与能量 | 峰值、平均值、占空比、持续时间 | 启动、加速、并发负载和转换损耗 |
| 热 | 产生、传递、散出和温度限制 | 环境温度、热惯性、接触与降额 |
| 带宽与计算 | 峰值流量、处理开销和共享竞争 | 协议开销、突发数据、异常重试 |
| 时间 | 各段延迟、抖动和截止期 | 最坏执行、排队、同步与模式切换 |

余量需要写明计算式、对应工况和持有方。设计早期的估计值会随成熟度增长，常见做法是按成熟度设置增长余量，并随设计冻结逐步释放，而不是在一开始给一个固定百分比。

**取舍需要留下可复查的依据。** 分配方案通常不唯一。权衡时先列出真正不同的候选方案（包括维持现状），从要求导出判据，并区分门槛判据（不满足即淘汰）和比较判据（参与打分）。每项打分写明依据与不确定范围；加权求和要求各判据可以相互补偿，单位不同的指标先归一化。最后检查权重或关键分数在合理范围内变化时，推荐方案是否改变；若改变，应优先补证该参数。[R9]

**技术风险需要登记和跟踪。** 风险是尚未发生、可能影响目标的不确定事件；已经发生的是问题，不再按风险管理。一条风险写成“因为某条件，可能发生某事件，导致某后果”，并记录可能性、后果、责任人、缓解措施、触发条件与复查日期。[R8] 新技术的成熟度可以用 TRL 1–9 描述[R18]；已在一种环境中成熟的技术，用到新的环境、规模或接口时需要重新评估。

**工作产物：** 指标分解与回算表、误差预算、按工况分列的资源账本、权衡记录和风险登记。检查时应能指出最紧约束、主要贡献项和余量的定义；同一份余量不能被多个团队重复使用；还应能说明为什么选这个方案，哪项假设变化会推翻它。

## 把接口、时序与运行前提一起设计

接口需要说明双方如何相互作用。机械连接之外，还有载荷、热、电气参考、阻抗、数据语义和操作者动作。接口定义应覆盖正常工作，也应覆盖无效输入、超时、断连、恢复和版本不匹配。[R2]

对于一项传感器数据，至少可以沿着“物理事件—传感—调理—采样—处理—传输—使用—执行”追踪幅值、带宽和时间。同步、固定延迟、随机抖动和时钟漂移对系统的影响不同。移动对象的位置误差可在适当近似下用速度乘以时间误差估计。

信号链中有几项常被忽略的约束：

- **采样与混叠。** 以采样率 f_s 采样时，高于 f_s/2 的分量会折叠到低频，采样后无法再与真实低频信号区分。抗混叠滤波必须放在采样之前；数字滤波不能修复已经发生的混叠。
- **有效分辨率。** ADC 位数不等于有效分辨率。可用有效位数 ENOB = (SINAD − 1.76 dB) / 6.02 dB 表达，其中 SINAD 应在实际输入频率和幅值下测得。
- **滤波的代价。** 滤波可能改善噪声，也会改变幅值、相位、峰值和延迟，这些变化需要进入时序预算和控制回路模型。

物理耦合同样需要分析。负载改变可能引起压降、温升、变形和振动，继而改变传感器或执行器的表现。对执行器，幅值限制、速率限制和持续工作能力应进入模型；对电源和热设计，峰值和累积效应分别校核。电气接口还需检查参考电位、接地路径、共模电压和屏蔽端接；多点接地形成的环路、开关电源和电机驱动的共模噪声，常以“偶发跳变”“读数随负载变化”的形式出现。发射和抗扰度要求按产品适用的标准确定，例如 IEC 61000 系列及相关产品标准。[R17]

**反馈回路把时序问题变成稳定性问题。** 闭环性能不能只用“响应快、不超调”描述，应同时规定跟踪、扰动抑制、噪声敏感和鲁棒性，并说明在哪个频率范围或哪类输入下成立。[R10]

| 要规定的方面 | 常用表征 | 需要说明的条件 |
| --- | --- | --- |
| 跟踪 | 阶跃或斜坡响应的上升时间、超调、调节时间；规定频率范围内的跟踪误差 | 输入幅值、是否进入饱和、完成判据 |
| 带宽 | 穿越频率 ω_c，或 \|T(jω)\| 下降 3 dB 的频率 | 采用哪一种定义 |
| 扰动抑制 | 各频率处 \|S(jω)\| 或 \|P S(jω)\| 的上限 | 扰动加在哪里（见[系统灵敏度](concepts/sensitivity.md)） |
| 噪声与测量误差 | \|T(jω)\| 在高频的衰减 | 传感器噪声谱和偏置 |
| 鲁棒性 | 增益裕度、相位裕度、模值裕度（\|S\| 峰值 M_s 的倒数） | 模型不确定性范围、对象参数变化 |
| 大信号行为 | 饱和、速率限制、抗积分饱和后的恢复 | 最大指令、最坏负载 |

纯延迟 τ 在频率 ω 处带来 ωτ 弧度的相位滞后。例如穿越频率 20 Hz（ω_c ≈ 125.7 rad/s）、端到端延迟 2 ms 时，相位裕度减少约 0.251 rad，即 14.4°；零阶保持器约贡献半个采样周期的等效延迟。因此时序预算必须与回路设计一起评审。S 与 T 也不能在同一频率同时很小：对开环稳定、相对阶不低于 2 的回路，Bode 灵敏度积分给出 ∫₀^∞ ln\|S(jω)\| dω = 0（开环有右半平面极点时右端为正），某些频率的扰动抑制改善，必然在另一些频率变差。柔性模态、齿隙、摩擦和饱和常常比控制算法更早决定可达带宽，线性小信号模型的裕度不能代表大信号工况。

运行状态决定哪些设计条件已经成立。启动、预热、自检、标定、就绪、工作、降级和停机之间，需要明确进入条件、退出条件、超时和恢复路径。稳态试验无法替代这些转换过程的验证。涉及人身或设备安全的状态与互锁，按下文“安全”部分处理。

**工作产物：** 接口控制文件、信号链与端到端时序预算、控制性能规格与含延迟/饱和/主要模态的回路模型、状态转换表和运行包络。检查标准是接口双方能分别实现并正确处理异常，闭环在最坏参数组合下仍有规定的裕度，系统不会在前提缺失时进入不允许的工作状态。

## 让测量、数据与参数支撑结论

先定义被测量，再选择测量链。分辨率、重复性、准确度和量程分别描述不同能力；设备标称参数也不能代替当前安装、环境和校准状态下的测量能力。

标定建立示值与参考量值之间的关系，调整改变设备本身；标定后仍需记录残余不确定度、适用范围和重新标定的依据。参考设备和产品共享同一基准时，验证可能无法暴露部分共同误差，应在测量方案中分析。

用于验收或过程控制的测量系统，应在实际使用条件下证明其能力，而不是只看设备说明书：

- **重复性与再现性。** 重复性条件指同一程序、操作者、设备、地点和短时间内的重复测量；再现性条件改变操作者、设备或地点等因素。[R11] 两者的差异决定了测量结果能否在不同班组、不同工位之间互认。
- **量具重复性与再现性研究（Gage R&R）。** 用多个零件、多名操作者、重复测量，分离出测量系统变差与零件变差。汽车行业 MSA 手册常以测量系统变差占公差或过程变差的比例作参考：低于 10% 一般可接受，10%–30% 视用途决定，高于 30% 一般不可接受。[R12] 这些是行业经验，不是普遍阈值。
- **测量能力与判定规则。** 测量不确定度相对公差越大，误判概率越高。检测不确定度比（TUR）、保护带与误判概率可按 JCGM 106 处理；部分校准体系采用误判概率不超过 2% 或 TUR 不低于 4:1 作为要求。[R14]

原始数据、处理数据和展示数据应可区分。保留时间戳、单位、有效性、配置与处理参数。异常值处理应保留规则和被排除的数据，避免结果无法复现。

辨识参数时，需要保证试验对相关参数具有足够信息。拟合与验证使用适当独立的数据或工况，检查残差和参数区间。对经验模型与 AI 模型，还要说明训练、标定、验证与使用范围的关系，评估外推风险。

**工作产物：** 测量链、测量系统分析、标定记录、数据处理说明、参数来源和独立验证结果。检查时，另一位工程师应能从原始数据复现关键图表，并解释测量能力对结论的限制。

## 用逐级集成和可证伪假设定位问题

集成顺序按依赖关系设计。先确认接口和已知输入下的行为，再逐步引入真实负载、共享资源、动态工况和异常。每一步保留可恢复的配置及通过条件，使新问题的范围可以限制在较少的变化中。

问题记录先写事实：什么设备和版本，在什么条件下，出现了什么现象，发生顺序和数据是什么。随后提出能够被实验推翻的假设，设计分段测量、替代、对照或条件控制来区分原因。

| 容易无效的做法 | 更有信息量的动作 |
| --- | --- |
| 同时换件、改参数、改程序后宣布修复 | 记录每次变化，隔离关键因素，再检查交互作用 |
| 只有最终输出，没有中间测点 | 在关键关系两端建立观测，比较输入、预测和输出 |
| 把时间先后直接视为因果 | 通过对照、替代或受控干预检查解释 |
| 只验证正常运行 | 在原复现条件、边界和相关场景中回归 |

软件、处理器和硬件在环可按任务需要使用，选择依据是需要隔离哪类误差与风险。工具名称本身不决定证据强度。

**工作产物：** 集成阶梯、问题记录、假设与证据、修复和回归结果。检查时，根因解释应能覆盖原始现象，修复应能在同样条件下复测。

## 为制造差异、失效和长期使用保留空间

单台样机证明一次实现可行；制造与长期运行还会引入尺寸差异、装配、批次、环境、磨损和老化。关键特性应从系统功能传到制造与检验，再由实际数据确认一致性。

**公差分析。** 对线性尺寸链 Y = Σ aᵢXᵢ，各环公差为 Tᵢ：

| 方法 | 合成公差 | 成立前提 |
| --- | --- | --- |
| 极值法 | T_Y = Σ\|aᵢ\|Tᵢ | 无统计假设，保证全部组合；环数多时偏保守 |
| 平方和法（RSS） | T_Y = √(Σaᵢ²Tᵢ²) | 各环独立、分布居中、公差对应相同的标准差倍数 |
| 统计模拟 | 由抽样得到 Y 的分布 | 各环分布、均值偏移和相关性有数据依据 |

均值偏移和相关性会让平方和法明显偏乐观；涉及安全或装配干涉的关键链，应使用极值法或有数据支撑的统计模型。

**过程能力。** 批量生产能否稳定满足公差，可用 Cp = (USL − LSL) / (6σ) 与 Cpk = min(USL − μ, μ − LSL) / (3σ) 表征。这两个指标要求过程处于统计受控状态，且 σ 的估计方法要写明。[R13] “Cpk 不低于 1.33”之类是常见合同约定，不是物理规律。

**可靠性。** 可靠性、可用性、安全性与性能是不同的判断维度。可以使用 FMEA 梳理失效模式、原因与影响，用故障树检查多个事件如何组合。冗余需要同时考虑故障检测、切换覆盖和共同原因；两个部件共享供电、环境或软件时，不能直接假定独立。失效率、MTBF 等数字必须连同失效判据、环境和工作剖面一起给出。在恒定失效率假设下 R(t) = exp(−λt)，MTBF = 1/λ，而运行到 t = MTBF 时的可靠度只有 e⁻¹ ≈ 36.8%；MTBF 因此不是使用寿命，磨损型失效也不满足恒定失效率假设。元器件按降额规则使用，是把应力留在可靠性数据适用范围内的常用方法。

**环境与寿命试验。** 试验条件应从产品的环境剖面推导：运输、存储、安装和运行各阶段经历的温度、湿度、振动、冲击、气压和电磁环境。通用试验方法可参照 IEC 60068 系列，军用设备常按 MIL-STD-810 的剪裁思想推导试验，机载设备有 RTCA DO-160。[R17] 加速寿命试验需要有依据的加速模型，并确认加速应力下的失效机理与实际使用相同。

**安全。** 安全与可靠不是同一件事：一个从不失效的系统可能因设计本身伤人，一个经常失效的系统也可能每次都停在安全状态。安全工作从危险出发：确定预期用途、可合理预见的误用和各生命周期阶段；识别机械、电气、热、能量释放、控制失效和人机交互等危险（可用检查表、HAZOP，以及面向控制结构的 STPA）；结合严重程度与发生可能性估计并评价风险；再按 ISO 12100 的三步法降低风险，优先顺序为本质安全设计、安全防护与补充保护措施、使用信息，后一步不能替代前一步能做到的事情。[R15]

依靠控制系统实现的安全功能（急停、限速、限位、安全扭矩关断等），需要规定触发条件、要达到的安全状态、反应时间和所需完整性等级。[R16]

| 领域 | 常用标准 | 完整性表达 |
| --- | --- | --- |
| 通用电气/电子/可编程电子安全系统 | IEC 61508 | SIL 1–4 |
| 机械控制系统安全相关部件 | ISO 13849-1 | PL a–e |
| 道路车辆电子电气系统 | ISO 26262 | ASIL A–D |
| 民用航空系统与设备 | SAE ARP4754 / ARP4761 系列 | 研制保证等级 DAL A–E |

安全状态需要具体分析，“断电”并不总是安全：竖直轴断电会下落，需要抱闸并验证其保持能力；某些过程中途停止反而产生危险。还需检查诊断覆盖、共因失效和安全功能与普通控制功能之间的独立性。具体项目应按所在行业和地区的法规与标准执行，本节不替代合规评估。

规定故障后的可接受行为：停机、保留某种有限能力、告警、等待人工处理或按条件恢复。维护、重标定、更换与现场反馈应连接到模型、预算和验证，而不仅是独立的售后记录。

**工作产物：** 关键特性与公差分析、过程能力数据、FMEA、可靠性口径与环境试验依据、危险日志与安全要求、降级与恢复逻辑、维护和复验依据。检查时应能回答“哪项变化会先影响什么结果，如何发现，如何处置”，以及每一个已识别危险由哪项措施控制、怎样被验证、剩余风险由谁接受。

## 将验证、配置和方法资产连接起来

验证检查产品是否满足规定要求，确认检查产品是否适合预期用途。两者都需要在要求形成时考虑。[R1] 一个不可测或口径不清的指标，会在交付阶段转化为无法收敛的争论。

为每项关键要求指定分析、检查、演示或试验方法，说明工况、设备、样本和判据。均值、分位数、最大值、置信度和覆盖概率支持不同结论；重复测量还需要考虑样本独立性、相关性和工况覆盖。安全功能的验证还应包括故障注入。

例如，在独立同分布的伯努利模型下，3000 次零失败，对失败概率的单侧 95% 置信上限约为 0.10%，与“三分法则”的近似值 3/n 一致。报告“零失败”应连同样本数、模型假设和覆盖范围，不能直接推导失败概率为零。

配置基线同时包含实物、装配、固件/软件、参数、标定、模型、数据处理和工具版本。交付证据应指向这一组合。设计或环境改变后，需要重新评估哪些旧分析和试验仍然有效。[R5]

工程基础库可以由脚本、计算表、模板、测量流程和参考样例共同组成。复用前检查输入、单位、条件和版本；每项资产保留正常例、边界例、验证依据与适用范围。反复复制本身不能证明其可靠。

**工作产物：** 要求验证矩阵、统计试验记录、配置与证据索引、可复用方法包。最终应能说清哪一套配置、在什么条件下、依据什么证据、支持什么结论。

## 变更时怎样重新检查

| 变化 | 优先重新检查 |
| --- | --- |
| 改变总体指标或使用工况 | 模型适用范围、误差/资源预算、边界、危险分析和验收判据 |
| 更换传感器或安装位置 | 基准、标定、时间语义、误差、供电、接口和测量系统能力 |
| 改滤波、软件或处理频率 | 幅相与延迟、控制裕度、负载、数据处理、版本和回归 |
| 更换电源、驱动或机械结构 | 峰值、热、载荷、耦合、饱和、结构模态、安全状态和异常行为 |
| 更换供应商、工艺或批次 | 关键特性、公差、过程能力、资料口径和抽样验证 |
| 扩大环境或运行时间范围 | 漂移、老化、可靠性、环境试验、维护与重新标定 |
| 改变操作方式或使用人群 | 可预见误用、危险识别、使用信息和培训 |

## 如何判断能力已经形成

共性能力首先表现为能够解释、能够检查，并能独立完成一个小任务。跨专业骨干还需要把多个专业的模型、预算、接口与验证组织在一起。复杂热、结构、电磁、控制等问题，再按岗位与项目要求深化。

可以用以下问题自查：

- 能否把模糊需要改写为双方理解一致的通过条件？
- 能否对关键结论做数量级或独立方法校核？
- 能否将部件能力综合回总体要求，并解释相关性和余量？
- 能否说明为什么选这个方案，哪项假设变化会推翻它？
- 能否规定正常与异常接口行为，并追踪关键时间链和信号链？
- 能否说明闭环带宽、裕度和主要限制来自哪里？
- 能否设计测量和对照试验，逐步缩小故障原因，并证明测量系统足以支撑判定？
- 能否列出主要危险及其控制措施和验证方式？
- 能否把结果连同配置、原始数据、模型和限制交给另一位工程师复现？

熟练程度可参照 INCOSE 系统工程能力框架的五级划分[R19]，每级以可检查的产物作证据，而不以学时或职称作证据：

| 等级 | 能做到什么 | 可作为证据的产物 |
| --- | --- | --- |
| 1 认知 | 能解释概念，识别任务中缺了哪一项 | 对一份现有记录指出缺项并说明理由 |
| 2 在指导下实践 | 在模板和审查下完成一项工作产物 | 一份经审查修改后的误差预算或物理量字典 |
| 3 独立实践 | 独立完成一个小任务的完整记录，并通过他人复现 | 从要求到验证证据的完整任务记录 |
| 4 主导实践 | 组织多个专业的模型、预算、接口、安全与验证，指导他人 | 跨专业项目的预算体系、接口控制和评审记录 |
| 5 专家 | 制定组织级方法和判据，处理没有先例的问题 | 被组织采用的方法、模板或标准算例 |

这些能力通过反复完成任务及复盘积累。建议优先选择指标分解、误差分配、接口联调或一次故障定位，形成一份完整记录，再逐步增加复杂度。
