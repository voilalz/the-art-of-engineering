# 第1章 从一句要求，到一个工程问题

**所属主题：问题与模型｜版本：V0.1 研究正文初稿｜日期：2026-11-15**

## 1.1 工程问题的起点

“精度高、响应快、稳定可靠”表达了使用者关心的方向。要据此设计系统，还需要知道：系统用于什么任务，工作在什么条件下，哪个结果受到约束，数值要求从何而来，以及用什么证据判定满足要求。

即使要求写成“定位误差不超过1 mm”，问题也未必已经明确。这里的位置可能属于传感器安装点、工件中心或最终作用点；误差可能对应单轴、平面距离或三维距离；结果可能指测量时刻，也可能指下游执行时刻；“不超过”还可能被理解为确定性边界、样本最大值或某个统计分位值。

因此，工程要求的形成包含两项工作：一是把含义说清楚，二是为所要求的能力建立依据。前者使不同团队能够讨论同一个对象，后者说明为什么应采用这个指标及其数值。

本章采用如下研究立场：**从任务出发，通过系统边界、场景分析和适当模型形成候选要求，再以数据、独立校核和权衡逐步建立其可信依据。** 数值要求需要随证据成熟而收敛；继承的接口要求、法规约束和明确的上级要求，也应记录来源并检查影响。

本章的直接产物是“一页问题定义、场景清单、带条件和依据的要求条目”。达到本章目标，意味着两个团队面对同一条要求，能够说明同一个被测量或系统行为、同一类适用条件，以及相容的通过判据。

## 1.2 基本术语及其使用边界

### 1.2.1 任务、需要与要求

下表采用系统工程中的常用含义，并结合本章用途作中文释义。它们用于明确工作对象，不替代特定合同或行业规范的原文定义。[R1—R5]

| 术语 | 本章采用的定义 | 必须区分的内容 |
| --- | --- | --- |
| 系统 system | 为实现某种目的而相互作用的一组要素及其关系；要素可包含硬件、软件、人员和过程 | 系统不必等同于一台设备 |
| 关注系统 system of interest，SoI | 当前研究、设计或验证所针对的系统 | 关注系统之外仍可能存在必要依赖 |
| 利益相关方 stakeholder | 对系统提出需要、受到系统影响，或承担其生命周期责任的个人或组织 | 采购方、使用者、维护者的关切可能不同 |
| 需要 need | 利益相关方期待获得的能力、效果或所要解决的问题 | 可先定性表达，也可包含数值 |
| 要求 requirement | 经分析形成的、适用于某个实体的规定性义务，描述其应具备的功能、性能、特性或应满足的约束 | 一条要求应有明确对象、含义和可验证性 |
| 任务需要 mission needs | 本章特指从任务角度提出的预期结果、成功条件及相关限制 | 这是对需要来源的归类，不意味着其已全部转化为系统技术要求 |
| 系统要求 system requirements | 面向关注系统规定的功能、性能、接口、环境适应性及其他必要特性 | 应与任务需要、上级要求或外部约束保持可追溯关系 |
| 功能 function | 系统为实现目的而执行的动作、转换或行为 | “输出位置”描述功能，“误差多大”描述相应性能 |
| 性能 performance | 在规定条件下，功能或系统特性的可量化表现 | 必须说明量、单位、条件与判定口径 |

本章用“应”表达拟具有约束力的要求条款；“宜”表示推荐，“可”表示许可。正文解释、分析假设和未确认数值，不因使用规范性措辞就自动成为已批准要求。

需要与要求之间包含分析、协商与决策。例如，“便于维护”可以转化为可接近性、诊断、替换时间等要求；“采用某种处理器”则可能是架构选择，也可能是兼容既有系统的有效约束。后一种情况应记录为何必须限定实现方式。[R3][R4]

### 1.2.2 场景、约束与假设

| 术语 | 专业含义与本章工作性约定 | 记录时的重点 |
| --- | --- | --- |
| 运行概念 concept of operations，ConOps | 从运行角度说明系统如何在其生命周期和使用环境中满足相关方期望 | 谁使用、怎样协作、经历哪些阶段和异常 |
| 场景 scenario | 本章将其操作化为具有初始条件、参与对象、事件顺序、环境及预期结果的使用情形 | 不只记录一个静态工况点 |
| 任务剖面 mission profile | 本章指任务阶段及其时间顺序、持续时间、负载和环境等条件随过程的描述 | 明确哪些阶段串行、并行或重叠 |
| 工况 operating condition | 描述系统某次运行条件的状态或取值组合 | 负载、温度、速度、供电、工作模式等 |
| 约束 constraint | 限定允许行为或可选方案空间的条件 | 来源、适用范围、允许偏离的处理方式 |
| 假设 assumption | 为进行分析暂时接受、但其成立性仍需说明或检查的命题 | 依据、有效范围、确认方法和失效影响 |
| 系统边界 system boundary | 区分关注系统与外部实体的范围划分，并确定跨界交互 | 设计责任、外部接口、必要依赖 |
| 模型适用域 domain of applicability | 模型已有依据支持使用的条件、参数和用途范围 | 不能将系统工作范围直接当成已验证的模型范围 |

ConOps 与场景用于揭示正常及非正常使用下的行为和交互。[R2] 本章对“场景”“任务剖面”的字段划分是便于执行的方法约定，并非宣称所有行业使用统一模板。

约束和假设的区别尤其重要。“外部供电限制为某个范围”可能是必须满足的接口约束；“分析中暂按恒定供电处理”则是假设。假设写成图纸、程序参数或要求条目之后，仍需要证据，不能以书写形式代替成立依据。

### 1.2.3 模型、仿真与验证

模型 model 是为特定用途对对象、过程或关系作出的表达，可以采用图、逻辑、方程或其他形式。仿真 simulation 是使用模型重现或推演系统行为的活动；软件是模型和求解过程的一种实现载体。[R6]

本章区分三个对象：

- **要求的检查与确认：** 条目是否表达清楚，其内容是否正确承接任务需要且可以实现。
- **产品验证 verification：** 产品是否满足规定要求。
- **产品确认 validation：** 产品在预期环境中是否满足预期用途。

对模型还需要分别检查实现是否符合模型规定，以及模型对目标用途的代表程度。以上区分分别对应要求、产品或模型，不能仅凭同一个“验证”称呼认为工作已经相同。[R1][R5][R6]

## 1.3 先确定任务及系统边界

### 1.3.1 从使用结果识别技术问题

原始表述中的“精度高”，需要追溯到使用结果。若位置用于装配，应关注最终作用点相对装配基准的位置关系；若用于运动控制，还要明确结果对应的时刻和可用性；若用于尺寸检测，则需定义具体尺寸及其规定状态。

由此建立三个层次：

1. **任务结果：** 使用者最终需要完成什么，怎样识别成功、失败或不可接受的损失。
2. **系统责任：** 本系统应提供哪些功能和能力，哪些结果由其他系统共同完成。
3. **技术表征：** 用哪些可以分析或取得证据的量描述这些能力。

这三个层次应建立联系。仅提升一个容易测量的参数，未必改善任务结果；仅规定任务成功，也可能不足以指导负责某个子系统的团队。

### 1.3.2 将外部依赖写成明确条件

系统边界需要同时说明物理范围、功能责任和跨界交互。例如视觉定位模块可能依赖外部照明、安装基准、工件外观、同步时钟与下游执行机构。

| 依赖对象 | 需要约定的内容 | 未明确时的后果 |
| --- | --- | --- |
| 安装与机械基础 | 基准、位置、刚度、振动条件 | 模块内部误差小，作用点仍可能偏离 |
| 供电与散热 | 输入范围、峰值、连续运行条件 | 性能要求可能建立在无法保证的环境上 |
| 时间与通信 | 时间戳含义、传输条件、超时和数据有效性 | 不同时间的数据被当成同一状态 |
| 外部对象与操作者 | 对象可识别条件、操作前提、交互顺序 | 系统任务与使用方式不匹配 |
| 参考测量系统 | 参考量、安装方式和不确定度 | 无法判断测试差异来自产品还是参考链 |

每项关键依赖都应说明提供方、需要方、成立条件、异常处理及确认方式。这里的角色是责任字段，不预先指定某个真实组织。

### 1.3.3 按事件和状态展开场景

场景分析至少检查正常工作、启动、停止、异常与恢复。是否还需要运输、存储、维护等场景，由任务和生命周期范围决定。

| 场景 | 应研究的行为 | 可形成的要求类型 |
| --- | --- | --- |
| 正常工作 | 接受有效输入，完成指定任务 | 功能、误差、时间、吞吐量 |
| 启动 | 完成检查和必要准备，建立就绪状态 | 就绪条件、启动时间、未就绪时的行为 |
| 停止 | 处理中断或结束请求，进入规定状态 | 停止响应、未完成任务处理 |
| 异常 | 输入无效、目标丢失、外部依赖失效 | 检测、标记、告警、降级或停止 |
| 恢复 | 故障解除后重新建立工作条件 | 恢复前提、重置或重新标定、重新就绪 |

“稳定可靠”应在这些场景中展开。输出波动、闭环动态稳定、故障概率和故障后的可接受行为分别对应不同问题，不能用一个模糊形容词代替。

## 1.4 用模型连接任务与系统要求

### 1.4.1 两种相互关联的模型

任务层面的模型描述“系统能力如何影响任务结果”。可抽象写为：

$$
\mathbf r=\boldsymbol\Phi(\mathbf q,c).
\tag{1-1}
$$

系统层面的模型描述“设计和工况如何形成系统能力”：

$$
\mathbf q=\mathbf F(\mathbf p,\boldsymbol\theta,c).
\tag{1-2}
$$

| 符号 | 含义 |
| --- | --- |
| $\mathbf r$ | 任务效果或结果的表征，例如完成时间、成功率或产出质量 |
| $\mathbf q$ | 系统能力或性能量，例如定位误差、延迟、加速度能力 |
| $c$ | 规定任务条件，可包含配置、场景、环境及时间过程 |
| $\mathbf p$ | 可选择的设计变量，例如尺寸、器件组合或方案参数 |
| $\boldsymbol\theta$ | 模型中的物理或经验参数，例如质量、摩擦系数、固定处理开销 |
| $\boldsymbol\Phi,\mathbf F$ | 针对当前决策建立的关系，可为解析式、数值过程或经验证的经验关系 |

这些是本章的通用组织符号，具体工程中应重新定义变量及其量纲。模型参数中存在未知量时，要记录估计和不确定性；“设计变量”与“参数”取决于当前分析层级，并非永远固定的身份。

任务要求给出可接受的结果范围。通过式（1-1）反推系统能力，再用式（1-2）检查设计可行性。这个逆向过程可能得到多个可行组合，需要结合成本、资源、风险和其他约束选择。

### 1.4.2 从单个数值转向能力约束

将某项性能要求写为 $g_j(\mathbf q,c)\leq0$。例如误差上界要求可以写成“误差表征量减去允许值不大于零”。令 $\mathcal J(c)$ 表示在工况 c 下适用的要求编号集合，则该工况下的可接受能力集合为：

$$
\mathcal Q_{\mathrm{req}}(c)=
\left\{\mathbf q:\ g_j(\mathbf q,c)\leq0,\ \forall j\in\mathcal J(c)\right\}.
\tag{1-3}
$$

对规定场景集合 $\mathcal C$，应检查 $\mathbf F(\mathbf p,\boldsymbol\theta,c)\in\mathcal Q_{\mathrm{req}}(c)$ 是否在每个适用 c 下成立。未知参数的范围和随机变化需要另行处理，不能仅检查名义参数点。式（1-3）用于表达确定性性能约束，不直接替代功能、逻辑或概率要求；随机变化的处理见1.6节。

例如移动目标定位可能近似满足“空间误差与信息时延共同消耗位置容限”。这会给出两者之间的可行关系，而不是唯一的传感器精度和时延数值。

### 1.4.3 需要动态模型时，先定义状态与输入输出

一类连续时间系统可写为：

$$
\dot{\mathbf x}=\mathbf f(\mathbf x,\mathbf u,\mathbf d;\boldsymbol\theta),
\qquad
\mathbf y=\mathbf h(\mathbf x,\mathbf u,\mathbf d;\boldsymbol\theta).
\tag{1-4}
$$

$\mathbf x$ 为描述系统动态所采用的状态变量，$\mathbf u$ 为可施加的输入，$\mathbf d$ 为外部扰动或非控制输入，$\mathbf y$ 为关注输出。状态应与初始条件共同定义；输出不一定能够直接测量，实际观测链还可能需要单独模型。

式（1-4）适用于能由所列常微分关系表示的情形。离散事件、代数约束、分布参数或随机微分系统需要相应表达；不能把所有工程对象都强行写成这一形式。若扰动被建模为理想白噪声，还需要使用适当的随机过程模型，不能将其当成普通可微函数处理。

建模深度由决策决定。早期可以先采用几何、运动学、守恒或经验关系；增加动态细节时，应说明它解决了哪个原模型无法支持的判断。

## 1.5 把性能量定义到可判定的程度

### 1.5.1 被测量、参考量与误差

被测量 measurand 是拟测量的量。它的定义应包含对象及与该量有关的状态、条件等信息。[R7] “工件位置”通常还需说明工件哪个点、在哪个坐标系、对应哪个时刻。

VIM 将测量误差定义为测得量值与参考量值之差。[R8] 对位置向量，若被测点为 A、表达坐标系为 F，本章写为：

$$
\mathbf e_{\mathrm{ref}}(t)=
\hat{\mathbf p}^{F}_{A}(t)-\mathbf p^{F}_{A,\mathrm{ref}}(t).
\tag{1-5}
$$

两项必须对应同一点、同一时刻和同一基准。若实际位置为 $\mathbf p$、参考误差为 $\boldsymbol\delta_{\mathrm{ref}}=\mathbf p_{\mathrm{ref}}-\mathbf p$，则试验得到的差值满足 $\mathbf e_{\mathrm{ref}}=\mathbf e_{\mathrm{true}}-\boldsymbol\delta_{\mathrm{ref}}$。参考系统并不自动等于真值，需要评估其不确定度及共享误差来源。[R9]

测量不确定度 measurement uncertainty 是依据所用信息，表征赋予被测量的量值分散性的非负参数。[R9] 它描述结果所附带的信息状态，与实际误差、允许误差属于不同概念。

还应区分三个对象：测量误差是估计值与参考值的差；运动过程的跟踪误差（tracking error）是实际轨迹与期望轨迹的差；任务误差是任务结果相对可接受目标的偏离。它们可能通过模型关联，但不能直接共用一个“定位误差”名称。

### 1.5.2 误差的维度与统计口径

在二维位置任务中，可以定义径向误差：

$$
E_r=\|\mathbf e\|_2=\sqrt{e_x^2+e_y^2}.
\tag{1-6}
$$

“径向误差不超过1 mm”与“两轴各不超过1 mm”不是同一个要求。后一种允许的最大径向误差达到 $\sqrt2$ mm。标注“1 mm”时必须同时定义使用哪一种量。

| 表征量 | 定义重点 | 所需补充信息 |
| --- | --- | --- |
| 单次误差 | 一次结果与参考值的差 | 对象、时刻、参考能力 |
| 均方根误差 RMSE | 误差平方平均后开方 | 样本或总体定义、权重、工况与参考 |
| 标准差 | 围绕均值的分散性 | 是否去除偏差、条件、样本量及分母约定 |
| 误差分位值 | 某一比例结果不超过的误差值 | 比例、统计总体、尾部与估计方法 |
| 确定性误差边界 | 在规定输入与条件集合内允许的界 | 集合范围、边界依据及未覆盖项 |

准确度、精密度、分辨率、不确定度与允许误差之间的进一步区别，见项目的[测量性能概念辨析](../../docs/concepts/measurement-performance.md)。本章只要求将使用的口径写清，避免相互替代。

### 1.5.3 响应时间必须有起点与终点

时间要求应说明起始事件、结束事件、时间基准及适用场景。例如“收到有效任务指令”可以作为起点；“输出第一帧”“进入允许位置范围”和“持续满足稳定条件”是不同终点。

对一维定位任务，定义位置跟踪误差 $e_p(t)=p(t)-p_{\mathrm{cmd}}$。若要求位置跟踪误差和速度连续保持在规定范围内，保持时间为 $T_h$，可以定义：

$$
\begin{aligned}
t_{\mathrm{enter}}&=\inf\{t\geq t_0:\ |e_p(s)|\leq E_{\mathrm{req}},
\ |v(s)|\leq V_{\mathrm{settle}},\ \forall s\in[t,t+T_h]\},\\
t_{\mathrm{done}}&=t_{\mathrm{enter}}+T_h.
\end{aligned}
\tag{1-7}
$$

其中 $t_0$ 是规定起始事件的时刻，$E_{\mathrm{req}}$ 是允许的位置跟踪误差，$V_{\mathrm{settle}}$ 是稳定判定速度阈值。若集合为空，可将完成时间视为无穷大并按超时或失败处理。保持时间应计入完成时间，不能在计时结束后再补做稳定判定。

式（1-7）是本文示范的一种数学判据，不是所有定位任务都必须采用的规则。实际试验还要规定采样率、参考测量、滤波及连续条件如何取得证据，不能以有限离散采样直接宣称所有时刻均满足要求。

### 1.5.4 信息年龄会进入任务误差

设位置在 $t_m$ 测得，在 $t_o$ 被下游使用，信息年龄为 $\tau=t_o-t_m\geq0$。为突出时间作用，暂以实际位置作为理想参考，且假定直接使用旧测量、不做运动预测。则：

$$
\mathbf e_{\mathrm{use}}(t_o)=
\hat{\mathbf p}(t_m)-\mathbf p(t_o)
=\mathbf e_{\mathrm{meas}}(t_m)-\int_{t_m}^{t_o}\mathbf v(s)\,\mathrm ds.
\tag{1-8}
$$

若测量误差存在确定性上界 $E_m$，在整个信息年龄区间内速度满足 $\|\mathbf v(s)\|_2\leq v_{\max}$，由三角不等式得到：

$$
\|\mathbf e_{\mathrm{use}}\|_2\leq E_m+v_{\max}\tau.
\tag{1-9}
$$

所有长度和时间应采用一致单位。若只知道初始速度和加速度界，应重新推导运动项；若采用预测补偿，进入预算的是预测残差；若 $E_m$ 只是标准差，不能直接将式（1-9）称为确定性保证。

这个模型说明，任务位置容限可能由测量和信息年龄共同消耗。增加像素、位数或测量重复性，并不能自动消除时间相关偏差。

## 1.6 误差边界、统计概率与证据置信度

### 1.6.1 定义误差不以预先指定分布为前提

误差可以按量值差定义；在分析中，可把未知误差描述为有界量、随机变量或其他适当形式。采用什么描述，取决于任务要求和证据。

确定性要求可以写成：

$$
\sup_{\omega\in\Omega_c}\|\mathbf e(\omega,c)\|_2
\leq E_{\mathrm{req}}(c),\qquad c\in\mathcal C.
\tag{1-10}
$$

$\mathcal C$ 为规定场景集合，$\Omega_c$ 为该场景内考虑的输入、扰动及变化集合，$\omega$ 表示其中一种实现。界的成立需要对这些集合及模型给出依据。试验样本的最大值本身不是式（1-10）所要求的总体上界。

若对重复变化采用概率模型，则可规定：

$$
\Pr\{\|\mathbf e\|_2\leq E_{\mathrm{req}}(c)\mid c\}
\geq p_{\mathrm{req}}(c),\qquad c\in\mathcal C.
\tag{1-11}
$$

$p_{\mathrm{req}}$ 是要求的覆盖概率。式（1-11）没有要求误差必须服从正态分布；分布假设、参数、相关性和尾部描述均需有依据。一个工况内获得的分布，也不能自动推广到其他速度、温度或工作模式。

对各场景分别提出要求，与按某种场景出现频率混合后只要求总体平均通过率，是不同的规定。后者可能掩盖少见场景中的明显退化，应由任务需要明确选择。

### 1.6.2 单次、逐时刻和完整任务的成功率不同

令 $A_k$ 表示第 k 次关键输出满足误差、有效性和时间等条件。整个任务均满足条件的事件为：

$$
A_{\mathrm{mission}}=\bigcap_{k=1}^{K}A_k.
\tag{1-12}
$$

即使每次满足概率都为0.99，也不能直接声称任务成功率为0.99。在相互独立、概率相同的教学假设下，100次均满足的概率为 $0.99^{100}\approx0.366$；存在相关性时，不能继续直接使用乘积公式。

因此，概率要求应说明统计单位是一次测量、一次动作、一段时间还是一个完整任务。若定位误差只针对“有效输出”统计，还应另行规定无效、缺失和超时结果；不能将这些结果排除后，把条件统计量直接当作任务成功率。

### 1.6.3 验收置信度是关于证据的方法属性

覆盖概率描述所要求的总体表现；置信度描述统计推断程序的覆盖性质。两者不同。NIST 的统计容忍区间资料明确区分“覆盖总体的某个比例”与“以规定置信度支持这种覆盖”的问题。[R10]

一个简化例子可以说明证据成本。假设每次完整任务独立同分布，只有成功或失败两种结果，成功概率为 p，且判定无误；预先计划的 n 次试验全部成功。令 $0<\alpha<1$、$0<p_{\mathrm{req}}<1$。由二项分布的精确单侧界，在置信水平 $1-\alpha$ 下，成功概率下限为：

$$
p_L=\alpha^{1/n},\qquad
n\geq\frac{\ln\alpha}{\ln p_{\mathrm{req}}}
\quad\text{用于要求 }p_L\geq p_{\mathrm{req}}.
\tag{1-13}
$$

这是二项模型零失败特例的推导，精确二项区间方法参见[R11]。若仅作教学示范，取 $p_{\mathrm{req}}=0.99$、$1-\alpha=0.95$，至少需要299次全部成功的独立任务；此时 $p_L\approx0.99003$。

连续取得299帧相关数据，不自动等于299次独立任务。若分别保证多个工况，还需处理各工况证据与多重推断，不能用混合总体的通过率替代逐工况保证。参考设备误差、工况代表性、试验期间变化和成功判定规则，也会影响结论。这一节用于说明“要求是否可验证”，不替代具体统计试验设计。

## 1.7 指标数值应从哪里来

### 1.7.1 数值来源需要分类记录

| 来源 | 形成方式 | 需要保留的依据 |
| --- | --- | --- |
| 任务效果或物理关系 | 从任务成功条件反推系统能力 | 场景、关系模型、参数与推导 |
| 明确的上级或外部要求 | 继承合同、上级系统、兼容性或适用规范中的规定 | 具体来源、版本、适用条款与责任边界 |
| 架构分配和方案权衡 | 在总体约束内选择部件或子系统指标组合 | 分配关系、可行性、成本、资源与余量 |
| 经验或类比 | 采用历史试验、相似产品或专家估计 | 相似条件、差异、范围及后续确认方法 |

来源不同，使用方式也不同。继承要求需要确认其适用性；经验值应说明依据和限制；模型结果需要保存关键假设；尚未确认的数值不能以增加小数位数制造确定感。

### 1.7.2 一个几何推导的例子

假设理想圆轴进入理想圆孔，两轴线平行，暂不考虑姿态偏斜、接触摩擦和动态变形。若孔径为 D、轴径为 d，横向中心偏移的无干涉几何边界为：

$$
E_{\mathrm{geom}}=\frac{D-d}{2},\qquad D\geq d.
\tag{1-14}
$$

在这个教学模型中，D=10 mm、d=8 mm，对应边界1 mm；边界处为理想接触，实际装配还需相应裕量。若使用尺寸保证范围，则应基于 $D_{\min}$ 和 $d_{\max}$ 等最不利组合重新计算；若 $D_{\min}<d_{\max}$，不能继续把负间隙解释为允许位置误差。

这个1 mm约束的是装配时的整体相对位置。测量、安装、执行和其他来源会共同影响它，因此它不自动等于传感器的允许误差。误差分配需要在总体几何或任务关系内进行，不能只因某项部件资料写着“精度1 mm”就视为整体满足任务。

## 1.8 贯穿算例：从作业时间推导运动能力

### 1.8.1 任务与问题定义

考虑一维移动平台。教学任务表述为：

> 在规定配置和负载条件下，平台从静止开始，移动1 m，到达目标并完成定位；从接受有效指令到确认完成的总时间不超过2 s。

“完成定位”按式（1-7）定义，位置阈值、稳定速度阈值和保持时间仍需由具体作业要求确定。这里先研究时间与运动能力关系，不把尚未确定的定位阈值任意填成1 mm。

| 项目 | 教学模型取值或约定 | 当前依据状态 |
| --- | --- | --- |
| 移动距离 L | 1 m | 示例任务给定 |
| 总作业时间上限 $T_{\mathrm{req}}$ | 2 s | 示例任务给定，包含非运动开销 |
| 初始与末端速度 | 均为0 | 当前工况及简化模型边界条件 |
| 串行非运动时间 $\tau$ | 暂取0.2—0.4 s | 教学区间，实际须由接口、实现分析或实测确认 |
| 运动形式 | 先匀加速，再对称匀减速 | 第一版候选方案 |
| 暂未建模的因素 | 有限跃度、柔性、摩擦、驱动动态等 | 后续检查是否影响结论 |

本例将不重叠的准备、处理和完成确认开销合并为 $\tau$。实际存在阶段重叠、时间相关性，或稳定过程与轨迹耦合时，应更新分解，不能将同一时段重复相加。

### 1.8.2 先推导理想对称加减速关系

在理想运动模型中，$x(t)$ 为沿运动方向的位移，$v(t)=\mathrm dx/\mathrm dt$ 为速度，运动时间记为 $T_m$，加速度幅值为 $a>0$。起终状态满足：

$$
x(0)=0,\quad v(0)=0,\quad x(T_m)=L,\quad v(T_m)=0.
\tag{1-15}
$$

前半段加速度为 a，后半段为 -a，速度曲线为对称三角形。根据速度—时间曲线的面积：

$$
L=2\times\frac12\left(\frac{T_m}{2}\right)
\left(\frac{aT_m}{2}\right)=\frac{aT_m^2}{4}.
\tag{1-16}
$$

因此，为采用该轨迹在 $T_m$ 内完成移动，需要的加速度幅值和峰值速度分别为：

$$
a_{\mathrm{req}}=\frac{4L}{T_m^2},\qquad
v_{\mathrm{peak}}=\frac{a_{\mathrm{req}}T_m}{2}=\frac{2L}{T_m}.
\tag{1-17}
$$

等号表示使用全部运动时间的轨迹。将这些数值转成能力要求，还需满足实际可用加速度能力 $a_{\mathrm{cap}}\geq a_{\mathrm{req}}$，以及可用速度能力 $v_{\mathrm{cap}}\geq v_{\mathrm{peak}}$，并确认这些能力在规定负载和环境下能够实现。

若直接把总作业时间2 s当作运动时间，则得到 $a_{\mathrm{req}}=1\ \mathrm{m/s^2}$、$v_{\mathrm{peak}}=1\ \mathrm{m/s}$。它们只是遗漏非运动开销后的模型结果。

### 1.8.3 将任务剖面带回模型

对当前串行时间分解，有 $T_m\leq T_{\mathrm{req}}-\tau$。取全部可用运动时间，得到：

$$
a_{\mathrm{req}}(\tau)=\frac{4L}{(T_{\mathrm{req}}-\tau)^2},\qquad
v_{\mathrm{peak}}(\tau)=\frac{2L}{T_{\mathrm{req}}-\tau},
\quad 0\leq\tau<T_{\mathrm{req}}.
\tag{1-18}
$$

| 非运动时间 / s | 可用运动时间 / s | 所需加速度 / (m/s²) | 峰值速度 / (m/s) |
| --- | --- | --- | --- |
| 0 | 2.0 | 1.0000 | 1.0000 |
| 0.2 | 1.8 | 1.2346 | 1.1111 |
| 0.4 | 1.6 | 1.5625 | 1.2500 |

如果暂定开销区间确实覆盖任务条件，理想三角形轨迹在该区间内至少需要1.5625 m/s²的加速度能力和1.25 m/s的速度能力。这是指定模型下的能力组合，尚未计入未建模因素和额外设计余量，也不是所有可行轨迹的唯一组合。

数值后的小数位用于展示计算关系，并不意味着输入区间具有同样精度。设计文件应采用与输入证据相称的有效数字和范围表达。

### 1.8.4 用灵敏度确定下一项最有价值的信息

由式（1-18）：

$$
\frac{\partial a_{\mathrm{req}}}{\partial\tau}
=\frac{8L}{(T_{\mathrm{req}}-\tau)^3},\qquad
\frac{\mathrm da_{\mathrm{req}}}{a_{\mathrm{req}}}
\approx\frac{\mathrm dL}{L}-2\frac{\mathrm dT_m}{T_m}.
\tag{1-19}
$$

第一项导数的量纲为长度/时间³；后一关系是非零工作点附近的小变化近似。可用运动时间越短，开销估计对所需加速度的影响越强。

若某候选平台加速度能力仅为1.5 m/s²，当前开销区间已经足以使“能否按时完成”的结论发生变化。此时，优先确认时间边界和开销区间，可能比继续增加无关模型细节更有价值。该判断仍依赖当前模型覆盖了相关主要因素。

### 1.8.5 速度限制可能改变模型形式

假设候选平台 $a_{\mathrm{cap}}=1.6\ \mathrm{m/s^2}$、$v_{\mathrm{cap}}=1.0\ \mathrm{m/s}$。速度能力不足以实现表中的三角形速度曲线，应考虑具有匀速段的梯形曲线。

在点质量、起终速度为零、加减速度对称且幅值不超过 $a_{\mathrm{cap}}>0$、速度不超过 $v_{\mathrm{cap}}>0$、不限制跃度的理想模型中，对 $L\geq0$，最短运动时间为：

$$
T_{m,\min}=\begin{cases}
2\sqrt{L/a_{\mathrm{cap}}},&L\leq v_{\mathrm{cap}}^2/a_{\mathrm{cap}},\\
L/v_{\mathrm{cap}}+v_{\mathrm{cap}}/a_{\mathrm{cap}},&L>v_{\mathrm{cap}}^2/a_{\mathrm{cap}}.
\end{cases}
\tag{1-20}
$$

推导依据是：未达到速度上限时，采用最大幅值对称加减速，面积给出 $L=a_{\mathrm{cap}}T_m^2/4$；达到速度上限后，两段加减速总距离为 $v_{\mathrm{cap}}^2/a_{\mathrm{cap}}$，其余距离以 $v_{\mathrm{cap}}$ 运行。对于该理想模型，速度的可达包络限制了给定时间内的最大面积，从而得到上述最短时间。

代入当前参数，得到 $T_{m,\min}=1.625$ s；若开销为0.4 s，总时间为2.025 s，已超过2 s。忽略速度限制，仅凭“加速度1.6大于1.5625”就判定通过，会产生错误结论。

式（1-20）不能直接当成真实平台的完成时间预测。有限跃度、力矩与热限制、柔性及控制建立过程可能增加时间，实际轨迹和定位确认条件仍需检查。本例用于展示：**指标数值来自任务、约束和模型共同作用，任何一项改变都可能要求重新推导。**

## 1.9 粗模型何时足以支撑指标

### 1.9.1 判断依据是具体决策

粗模型的用途可以是估计数量级、排除方案、形成候选要求或支持最终指标。不同用途需要不同证据。NASA-STD-7009B 将模型预期用途、验证、确认、不确定性和灵敏度纳入接受与可信度评估。[R6]

在本项目中，建议采用以下判断问题。它们是本章的工作方法，不是引用标准中的统一分级或固定误差阈值。

| 问题 | 支持判断的材料 |
| --- | --- |
| 模型要支持什么决策 | 允许得出哪些结论，暂不支持哪些用途 |
| 主要影响机制是否覆盖 | 任务结果的关键因果链，以及遗漏因素的影响说明 |
| 输入是否有依据 | 实测、资料、类比或暂定来源，适用范围与不确定性 |
| 实现和推导是否正确 | 量纲、极限、守恒、独立计算或实现对照 |
| 结论是否对合理变化稳定 | 参数变化、工况变化和替代假设下的结果 |
| 证据强度是否匹配后果 | 决策代价、剩余余量及后续修正的可能性 |

“模型误差小于5%”不是适用于所有决策的充分条件。若剩余性能余量只有1%，5%的预测偏差就可能改变通过判断；而用于排除相差一个数量级的方案时，较粗的模型也可能提供有效信息。

余量本身同样需要依据。遗漏关键机制的模型即使给出很大数值余量，也不能据此自动认为可信。

### 1.9.2 区分不确定性的来源

| 来源 | 例子 | 优先的处理方式 |
| --- | --- | --- |
| 输入或参数知识不足 | 处理开销、摩擦、实际负载尚不明确 | 补充资料、测量或合理区间 |
| 模型结构差异 | 刚体模型忽略柔性，瞬时加速度模型忽略驱动动态 | 检查影响，必要时增加相关机制 |
| 数值与实现误差 | 步长、求解器、单位、程序实现问题 | 收敛与独立校核 |
| 场景或样本覆盖不足 | 只在常温、静止或单一工件上取得证据 | 补充代表性、边界与异常工况 |

范围或分布必须有来源，不能只为得到漂亮结果而选择。对尚无法量化的主要影响，应明确其存在和对当前结论的限制。

### 1.9.3 数值要求的成熟程度

| 状态 | 数值能支持什么 | 应保留的说明 |
| --- | --- | --- |
| 初步估算 | 数量级与明显不可行性判断 | 假设、简化关系和主要缺项 |
| 候选要求 | 方案研究与初步接口协商 | 范围、依据、待确认事项和风险 |
| 经论证要求 | 在明确条件下指导设计与验证 | 关键证据、可行性、余量和判定方法 |
| 受控基线 | 作为约定的设计输入与变更依据 | 批准范围、版本及变更影响 |

这些状态是本章建议的工作描述。TBD可用于尚待确定的值；TBR可用于已有候选值但仍需解决或确认的事项，具体管理约定应在项目中统一。[R4] 标注成熟状态，有助于防止初步计算值未经审查就成为不可更改的验收条件。

## 1.10 把分析写成可追溯的要求条目

### 1.10.1 条目正文与依据分开保存

一条性能要求的表达骨架可以是：

> 在【适用工况和状态】下，【系统或对象】应执行【行为】，其【明确定义的性能量】满足【阈值及统计口径】。

功能要求可以采用输入事件、响应行为和状态条件描述，不必强行增加数值。依据、推导和试验程序可作为关联属性保存，使正文保持清楚，同时不丢失数值来源。[R3][R5]

| 属性 | 应记录的内容 |
| --- | --- |
| 唯一标识与版本 | 能够引用和追踪的条目标识 |
| 正文 | 对象、条件、行为、性能量和通过条件 |
| 来源 | 任务需要、上级条目、接口或其他外部约束 |
| 数值依据 | 模型、公式、参数来源、假设和推导结果 |
| 适用范围 | 配置、工况、状态、时间和空间范围 |
| 验证策划 | 分析、检查、演示或试验，及关键判据 |
| 成熟状态 | 未确定、候选、经论证或已纳入基线 |
| 待解决项 | 未确认参数、影响、下一项证据及责任字段 |

### 1.10.2 移动平台示例的候选条目

以下条目属于教学问题定义，不是已经完成论证的真实设备规格。C-N表示已在场景清单中定义的正常定位工况，D-C表示需要另行定义的有效指令规则。

| 标识 | 候选正文 | 当前依据与待解决项 |
| --- | --- | --- |
| R-FUN-001 | 平台在就绪状态接收到符合D-C的指令后，应执行相应定位动作 | 任务责任；D-C的内容与范围待明确 |
| R-TIM-001 | 在C-N中，从接受有效指令的时刻到按式（1-7）确认完成的时间应不超过2 s | 示例任务给定；确认阈值和开销证据待补齐 |
| R-POS-001 | 在C-N的完成保持区间内，最终作用点相对目标基准的X向位置误差绝对值应不超过 $E_{\mathrm{req}}$ | $E_{\mathrm{req}}$ 为TBD，应由作业容限和总体关系推导 |
| R-STA-001 | 在未满足规定就绪条件时，平台应将状态报告为未就绪 | 就绪条件、状态接口待定义 |
| R-ABN-001 | 检测到规定的关键输入无效条件时，平台应报告相应无效状态 | 输入无效条件、检测时限和响应关联待定义 |

示例条目中仍存在显式待解决项，因此可用于讨论和完善，不应宣称已经满足完整、可验收要求。R-TIM-001和R-POS-001的联系应保留，避免时间判定与位置判定采用不同终点。

### 1.10.3 提前考虑证据和判定能力

分析利用模型或已有证据推导符合性；检查核查可观察特征、文件或配置；演示通过操作展示行为；试验在受控条件下取得测量数据。具体要求可采用适当组合。[R1]

涉及测量时，应定义参考链、不确定度、采样和处理，以及如何对接近边界的结果作判定。扩展不确定度通常对应规定覆盖条件，不能未经说明当成绝对最大误差；“测得小于限值”也不自动代表对实际性能具有任意强度的保证。[R9][R12][R13]

要求的检查与确认还需覆盖：是否确有任务依据，是否属于本层级，是否可实现，是否冲突或重复，是否过早限定实现方式，以及现有资源是否允许取得所需证据。

## 1.11 本章的最小工作产物

### 1.11.1 一页式问题定义

下表以移动平台任务示范填写方式。待定项保留为待定，避免通过未经论证的数字掩盖缺项。

| 字段 | 示例内容 |
| --- | --- |
| 问题与目的 | 在明确作业周期内完成指定工件的移动定位 |
| 任务结果 | 从有效指令接受到定位完成，移动1 m，总时间不超过2 s |
| 关注系统 | 平台运动与定位控制整体；具体机械、驱动和软件边界需在接口图中明确 |
| 任务范围 | 本次研究正常单次动作；启动、停止、异常与恢复另列场景要求 |
| 初始与结束条件 | 初始静止；结束按位置、速度和保持时间共同判定 |
| 对象与基准 | 最终作用点的X向位置；机械基准、参考测量及时间基准待明确 |
| 已知约束 | 时间和移动距离来自示例任务；负载、速度能力及环境范围待补齐 |
| 初始模型 | 一维点质量与理想加减速；串行非运动开销采用暂定区间 |
| 初步结论 | 运动能力需同时检查加速度与速度限制，1 m/s²不能直接作为完整指标 |
| 关键假设与缺项 | 开销范围、有限跃度、驱动与柔性影响，以及定位阈值依据 |
| 证据入口 | 本章公式、开销分析或实测、候选平台能力资料、后续试验记录 |
| 当前状态与下一项工作 | 候选要求阶段；优先确认计时边界和开销，并补齐定位完成条件 |

### 1.11.2 场景清单

| 标识 | 初始条件与触发事件 | 预期行为或结果 | 应补齐的依据 |
| --- | --- | --- | --- |
| C-N | 就绪、初始静止、有效指令、规定配置与负载 | 完成指定定位并报告完成 | 误差、时间与完成判定 |
| C-START | 系统启动或复位 | 完成必要检查，按条件建立就绪 | 检查内容、外部依赖、允许时间 |
| C-STOP | 正常动作中收到规定停止请求 | 按已定义的停止语义处理任务并报告状态 | 停止类型、允许范围和后续状态 |
| C-ABN | 关键输入无效或规定外部依赖失效 | 识别异常并执行已约定响应 | 检测能力、时限及失效影响 |
| C-REC | 异常原因解除 | 按前提恢复或要求重新准备 | 恢复条件、确认方法和重新就绪 |

清单中不能仅写“异常时保证可靠”。应继续描述可识别的触发、系统响应和可检查的结果。对未覆盖场景应明确范围，不能用正常动作试验代替全部生命周期证明。

### 1.11.3 要求与依据关联记录

除1.10节的条目正文外，至少为关键性能量保留下列关系：

| 任务需要 | 系统要求 | 推导或来源 | 当前限制 | 验证入口 |
| --- | --- | --- | --- | --- |
| 按时完成动作 | 总时间不超过2 s | 示例任务及完成事件定义 | 完成阈值尚未全部确认 | 时间链分析和带配置记录的试验 |
| 实现指定移动 | 运动能力满足时间关系 | 式（1-16）至式（1-20） | 理想运动与暂定开销 | 负载下能力、实际轨迹及开销测量 |
| 达到作业允许位置 | 作用点位置误差满足任务容限 | 作业几何或效果关系；当前TBD | 不能用参考仪器分辨率替代要求依据 | 任务关系、误差预算与参考测量链 |

## 1.12 常见错误与审查要点

| 常见问题 | 为什么会影响工程结论 | 应采取的动作 |
| --- | --- | --- |
| 直接把“精度高”改成一个小数值 | 任务关联和阈值依据仍然缺失 | 先定义对象和结果，再给推导来源 |
| 默认误差服从正态分布 | 尾部、偏差或工况差异可能改变结论 | 依据机理和数据选择表征，记录范围 |
| 只规定输出误差，排除无效或超时 | 条件表现被当成整体任务表现 | 将有效性、时间和失败行为纳入任务事件 |
| 将总作业时间等同于纯运动时间 | 遗漏等待和确认，或重复计算重叠阶段 | 建立时间剖面，明确各段起止与组合 |
| 用初步模型值直接冻结指标 | 参数、模型与场景证据可能尚不支持该用途 | 标注成熟状态，补齐关键证据 |
| 只检查一个能力指标 | 其他限制可能改变模型和可行性 | 联合检查相关约束并回代任务 |
| 以高保真或软件成功结束代替可信度 | 复杂度和正确求解不自动保证模型适用 | 检查用途、数据、独立校核和缺项影响 |
| 把扩展不确定度当成绝对最大误差 | 覆盖条件与确定性保证混淆 | 明确不确定度含义和符合性判定规则 |
| 认为所有实现方式都不允许写入要求 | 兼容性或其他明确外部约束可能必须限定实现 | 记录限定方式的依据及影响 |

审查本章产物时，应能回答：

1. 要求描述的结果是否真正对应任务需要？
2. 对象、基准、时刻、条件与状态是否足够明确？
3. 数值来自任务推导、继承约束、分配还是经验，能否追溯？
4. 模型、参数和适用范围是否支持当前决策？
5. 合理变化是否可能改变通过判断，相关影响是否已经处理？
6. 边界、概率、置信度与参考测量能力是否分别说明？
7. 两个团队能否按同一量定义和相容判据独立完成验证？

本章形成的是工程问题及其要求依据。后续建模、误差分配、详细设计和验证工作，都应能回到这些依据，并在任务或证据变化时更新它们。
