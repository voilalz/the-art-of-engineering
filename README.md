# 工程师的自我修养

**The Art of Engineering — 模型、预算、接口与验证**

一个面向机械、电子电气、仪器、控制、自动化、机器人与航空航天工程师的共性能力知识库。

这里持续整理一组反复出现在不同项目中的方法：把要求写清楚，把指标分解下去，把误差与资源算明白，让部件正确连接，在真实环境中完成验证，并留下可以复用的工程资产。

核心问题是：**怎样把局部正确的专业设计，变成可运行、可验证、可复现、可维护的工程系统？**

## 从哪些问题开始

专业公式、算法和器件选型之外，许多困难出现在专业之间、阶段之间和工况之间：

- 每个部件的精度都达标，整机却达不到总体要求。
- 数据能收到，单位、坐标、参考点或时间含义却没有对齐。
- 静态实验很好，运动、升温或负载变化后误差明显增加。
- 稳态运行正常，上电、切换模式和恢复故障时出现异常。
- 第一台样机通过，换批次、参数或软件版本后无法复现。
- 测试报告写着“通过”，却说不清适用工况和结论的统计强度。

本项目把这些现象变成可以分析、记录和检查的工作方法。每项方法都围绕四件事展开：**要解决什么问题、依据什么模型、形成什么产物、怎样证明有效。**

## 程序员的底层机制，给工程师什么启发

《程序员的自我修养——链接、装载与库》深入讨论程序构建与运行背后的机制。沿着同样的追问方式，工程师也需要理解专业模块之外的共同支撑条件。

| 程序员熟悉的机制 | 工程中反复遇到的问题 | 对应的共性能力 |
| --- | --- | --- |
| 类型、符号与调用约定 | 同一个量在双方那里是否含义一致 | 单位、量纲、基准、坐标与数据语义 |
| 链接与依赖 | 部件怎样正确组成系统 | 接口契约、耦合分析、依赖与集成顺序 |
| 装载与初始化 | 系统具备哪些前提才允许开始工作 | 上电、自检、预热、标定、状态与互锁 |
| 运行库与基础库 | 哪些可靠方法值得反复使用 | 数据处理、换算、误差计算、校核与记录模板 |
| 操作系统的调度与资源管理 | 时间、能源、热和带宽怎样协调 | 时序与资源预算、模式管理、余量与保护 |
| 并发与共享状态 | 多个环节同时作用会发生什么 | 同步、因果分析、共享误差与反馈耦合 |
| 调试与性能分析 | 偏差来自哪里，瓶颈在哪里 | 测量链、可观测性、日志、残差与故障定位 |
| 构建与依赖版本 | 为什么这次能工作，下次不能 | 配置基线、变更影响、回归与可复现交付 |

这些对应关系用于帮助理解。物理工程还需要正面处理制造差异、环境、磨损、老化、测量不确定度和不可消除的误差。

## 先把常用概念分清

讨论“精度高”之前，先分开结果偏多少、重复散多大、能分辨多少，以及不确定度和允许误差分别是多少。讨论“灵敏度高”之前，先说明谁对谁、在哪个工作点或频率上敏感。

- [精度、误差与分辨率](docs/concepts/measurement-performance.md)：准确度、正确度、精密度、分辨率和不确定度的分工，附一组读数与量化例子。
- [系统灵敏度](docs/concepts/sensitivity.md)：测量转换斜率、误差传播偏导数、相对灵敏度与反馈 S/T 的区别，附温度传感器和控制例子。
- [误差统计口径](docs/concepts/error-statistics.md)：标准差、RMS/RMSE、最大误差与分位值的定义、恒成立关系和换算前提，附误差预算案例的各口径对照。

这些辨析用于改变选型、标定、误差分配和验收方法。[概念辨析入口](docs/concepts/README.md)同时记录后续待解决的问题。

## 怎样开始使用

从手头一个范围足够小的任务开始，例如传感器更换、定位精度改进、供电升级或一次接口联调。

1. **定义结果。** 说明对象、场景、工况、指标及通过条件，先统一单位与基准。
2. **建立关系。** 写出最小可用模型，列清假设、输入来源和独立校核方法。
3. **分配预算。** 回算部件对总体的贡献，检查误差、资源、时间与余量。
4. **规定连接。** 明确接口、状态、异常语义和变更责任，按依赖关系逐级集成。
5. **取得证据。** 记录测量链、原始数据、统计口径、版本与适用限制。
6. **留下资产。** 将验证过的方法、样例与配置整理成下一次可正确复用的材料。

可以先复制[任务模板](templates/engineering-task.md)，再按[能力框架](docs/engineering-framework.md)检查缺项。涉及精度指标时，结合[误差预算案例](examples/error-budget.md)建立自己的分配和验证方法。

## 重点方法：误差分配

“总体精度 0.5 mm，各部件应该分多少”是工程中常见的问法。“精度”在这里还不是可验证的指标，下例先把它定义为一个带工况的概率要求。回答这个问题需要的不只是一个开方公式，还包括指标的统计含义、误差作用链、相关性、可标定性、成本和验证能力。

[教学案例](examples/error-budget.md)假设一个视觉检测定位台，要求在规定稳态工况下，X 向误差绝对值不超过 0.50 mm 的概率至少为 95%。在给定偏差上界和随机误差模型下：

| 假设 | 合成标准差 | 保守 95% 覆盖校核值 | 距离 0.50 mm 要求的余量 |
| --- | --- | --- | --- |
| 五项随机误差独立 | 0.155 mm | 0.384 mm | 0.116 mm |
| 视觉与平台误差相关系数为 0.8 | 0.192 mm | 0.457 mm | 0.043 mm |

单项指标没有变化，相关性就能显著压缩总体余量。使用预算时，需要把模型假设、部件能力和实测证据放在一起检查。

## 共同遵守的工作约定

- **数字有定义：** 单位、工况、基准和统计含义明确。
- **模型有边界：** 记录假设、参数来源、适用范围与失效条件。
- **预算能回算：** 子系统指标能够综合回总体要求，共享来源避免重复计入。
- **结论有证据：** 原始数据、处理过程、配置和判据能够追溯。
- **变更有影响分析：** 更换器件、参数或环境后，重新检查相关模型、预算与验证项。
- **复用有适用条件：** 模板、脚本和模型经验证后，保留版本、参考样例与限制。

参与者可以按自己的角色深化相关能力。复杂的热、结构、电磁、控制和安全问题，应结合相应专业的计算与行业要求。

## 后续积累方向

优先补充可用于实际工作的小案例和工作件：指标分解、接口控制、时序预算、标定记录、故障定位、统计试验和配置追溯。每新增一项，都给出计算或试验依据、适用条件和检查方法。

欢迎通过 Issue 记录具体问题，通过 Pull Request 补充案例、改进模板或修正方法。描述时请保留场景、模型、证据与限制，便于其他工程师复现和判断。
